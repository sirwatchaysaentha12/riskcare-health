## 2. Root Cause ของ "7day_mean ±2 เท่ากันทุก horizon (39.9%)"

**ไม่ใช่บั๊กโค้ด — เป็นสมบัติ horizon-invariance ของตัวทำนาย:**

`7day_mean` ทำนายด้วยค่า rolling-mean 7 วัน (rm_7d) **ณ วัน origin เสมอ ไม่ว่า horizon จะกี่วัน** และ rm_7d เปลี่ยนช้ามากระหว่างวัน (เฉลี่ย 7 วันเกลาความผันผวนหมด) → ค่าทำนายที่ใช้กับ h=1 กับ h=7 แทบเป็นค่าเดียวกัน → การกระจาย error = |target − rm_7d| แทบไม่ขึ้นกับ h → ±2 แบนราบทุก horizon

**พิสูจน์ด้วย eval ใหม่ที่สะอาด (rm_7d ใช้ shift(1) ป้องกัน leakage):**

| horizon | 7day_mean ±2 | 7day_mean ±3 | MAE |
|---|---|---|---|
| h=1 | 37.3% | 51.3% | 3.52 |
| h=2 | 33.3% | 45.6% | 3.75 |
| h=3 | 28.5% | 42.4% | 3.89 |
| h=5 | 29.0% | 42.0% | 3.92 |
| h=7 | 30.3% | 43.2% | 3.81 |

±2 แบนราบในย่าน 28–37% ทุก horizon — ยืนยัน root cause คือ invariance ไม่ใช่การ reuse ผลผิด ส่วนตัวเลข 39.9% เดิมต่างจากช่วง eval เดิม (window/สถานีต่างกัน)

**บั๊กจริงที่เจอและแก้รอบนี้ (Series ambiguity):** persistence เดิมอ้าง `s_all[origin]` จาก index รวมทุกสถานี เมื่อหลายสถานีมี timestamp เดียวกัน `s_all[origin]` คืน Series ทั้งก้อนแทน scalar → `ValueError: truth value of a Series is ambiguous` — แก้โดยใช้ค่า `pm25` ของแถวใน `daily_feats` โดยตรง (ต่อสถานีอยู่แล้ว)

## 3. ผลเทียบโมเดลทั้งหมด (holdout ≥ 2026-08-15, n=150)

| horizon | persistence ±3 / ±2 / MAE | 7day_mean ±3 | Ridge ±3 | HGB ±3 | Ensemble ±3 | ผู้ชนะ |
|---|---|---|---|---|---|---|
| h=1 | **78.0** / 60.7 / 2.07 | 51.3 | 49.3 | 54.0 | 60.7 | persistence |
| h=2 | **57.1** / 42.2 / 3.16 | 45.6 | 46.3 | 53.7 | 53.1 | persistence |
| h=3 | **52.1** / 31.2 / 3.81 | 42.4 | 51.4 | 46.5 | 50.7 | persistence |
| h=5 | 44.2 / 23.9 / 4.54 | 42.0 | 48.6 | 44.9 | **51.4** / MAE 3.91 | Ensemble |
| h=7 | 38.6 / 20.5 / 4.64 | 43.2 | 43.2 | **53.0** / MAE 3.46 | 49.2 | HGB |

- **persistence ยังครอง h=1–3** ทั้ง ±3 และ MAE (bias-corrected ไม่ช่วย: +bc ดีขึ้นสูงสุด 1.4 จุดที่ h=3/5)
- **ML เอาชนะได้จริงเฉพาะ h≥5**: Ensemble ที่ h=5 (+7.2 จุด ±3, MAE ดีกว่า 0.63), HGB ที่ h=7 (+14.4 จุด ±3, MAE ดีกว่า 1.18)
- 7day_mean แพ้ persistence ทุก horizon ≤3 และไม่เคยชนะโมเดลไหนเป็นตัวเลือกแรก

## 4. Ceiling Analysis — "±3 @87–90% ทำได้จริงไหม"

เพดาน noise floor = สัดส่วนที่ |pm25[t+h] − pm25[t]| ≤ K ของข้อมูลจริง (persistence ทำได้ไม่เกินนี้; โมเดลที่ทำนายจากประวัติ PM2.5 อย่างเดียวแทบข้ามเพดานนี้ไม่ได้):

| horizon | share(≤2) | share(≤3) | median \|Δ_h\| |
|---|---|---|---|
| h=1 | 37.6% | 50.2% | 2.98 |
| h=2 | 25.9% | 36.7% | 4.86 |
| h=3 | 23.5% | 33.2% | 5.19 |
| h=5 | 21.1% | 31.7% | 5.50 |
| h=7 | 20.3% | 29.6% | 6.04 |

**คำตอบ: ไม่ทำได้จากข้อมูล PM2.5 รายวันอย่างเดียว**
- ทั้ง dataset: **ครึ่งหนึ่งของวัน (50.2%) ค่า PM2.5 เปลี่ยน >±3 ใน 1 วัน** — ต่อให้ทำนายแม่นเทียบเท่ารู้อนาคต ตัวทำนายแบบ "ค่าล่าสุด/ค่าเฉลี่ย" ก็ติดเพดาน ~50% ที่ h=1 และตกเหลือ ~30% ที่ h=7
- holdout (ส.ค.-ต.ค. 2026) เพดานสูงกว่า (78% ที่ h=1) เพราะเป็นฤดูเงียบ — **อย่าสรุปความแม่นจาก holdout เดียว** (test-window artifact เดิมซ้ำรอบใหม่)
- ทางเดียวที่จะไปถึง 87–90% @±3: (ก) เปลี่ยนนิยามเป้าหมายเป็น band/category accuracy แทน ±µg/m³ คงที่, (ข) เพิ่มข้อมูล exogenous (พยากรณ์อากาศ, hotspot, CAMS aerosol), (ค) ใช้ hourly + โมเดลรายชั่วโมง (แต่ h=24–72 เคย FAIL 31–50%)
