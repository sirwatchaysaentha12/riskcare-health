# Checklist ทดสอบกล้องด้วยตนเอง

ใช้ทดสอบ prototype บน browser จริงเท่านั้น ผลนี้ไม่ใช่การรับรองทางการแพทย์ ห้ามบันทึกหรือส่งภาพใบหน้า วิดีโอ เสียง หรือข้อมูลสุขภาพส่วนบุคคลกลับมา

## เตรียมทดสอบ

1. เปิด PowerShell แล้วรัน:

   ```powershell
   Set-Location 'C:\Users\ACER\projectweb\frontend'
   npm run dev
   ```

2. เปิด URL ที่ Vite แสดง ตามด้วย `/breathing-check` โดยใช้ `localhost` หรือ HTTPS
3. จด browser/version, อุปกรณ์/OS และขนาดหน้าจอโดยประมาณ
4. ทดสอบทีละกรณีและกรอก PASS/FAIL พร้อมหมายเหตุที่ไม่มีข้อมูลส่วนตัว

> ปัจจุบันระบบวัด 30 วินาทีและไม่มีกราฟสัญญาณบน UI ดังนั้นการเทียบกับการนับ 60 วินาทีและการตรวจ “กราฟขยับตามลมหายใจ” ยังไม่รองรับครบ ให้บันทึก FAIL หรือ “ยังไม่รองรับ” ตามผลจริง ห้ามอนุมานว่าผ่านจากการเห็นค่า BPM

## Checklist

| สิ่งที่ทำ | ผลที่คาดหวัง | PASS/FAIL | หมายเหตุ |
|---|---|---|---|
| เปิดหน้าประเมินโดยยังไม่กดยินยอม | กล้องไม่เปิดและไม่มีภาพ preview |  |  |
| ติ๊ก Consent แล้วกดเปิดกล้อง จากนั้นกด Allow | Browser อนุญาตและแสดง preview |  |  |
| เปิดหน้าใหม่แล้วกด Deny/Block | มีข้อความปฏิเสธสิทธิ์และปุ่มลองใหม่ |  |  |
| อนุญาต permission หลังเคย Deny แล้วลองใหม่ | กล้องเริ่มขอ permission/แสดง preview ได้ |  |  |
| ถอดหรือปิดกล้องระหว่าง preview | แสดง error ไม่ค้าง และไม่เริ่มวัดต่อ |  |  |
| ออกจากหน้าเมื่อกล้องกำลังทำงาน | Camera Track หยุดและไฟ LED กล้องดับ |  |  |
| ทดสอบในแสงปกติ | Quality Gate ผ่านเมื่อการจัดเฟรม/เงื่อนไขอื่นพร้อม |  |  |
| ลดแสงในห้อง | แจ้งเพิ่มแสงและปุ่มเริ่มวัดไม่พร้อมเมื่อ gate ไม่ผ่าน |  |  |
| หันกล้องเข้าหาแสงย้อน | แจ้งภาพสว่างจ้าหรือคุณภาพไม่พร้อม หากตรวจพบ |  |  |
| ทำภาพเบลอ/หลุดโฟกัส | แจ้งรายละเอียดภาพไม่พอและไม่ให้เริ่มเมื่อ gate ไม่ผ่าน |  |  |
| จัดช่วงทรวงอกให้อยู่นอกกรอบ | แจ้งจัดเฟรมใหม่และไม่ให้เริ่มเมื่อ gate ไม่ผ่าน |  |  |
| ใส่เสื้อหนา | บันทึกว่าระบบยังเห็น/ไม่เห็น landmark; ห้ามตีความว่าเห็นการเคลื่อนไหวผ่านเสื้อหนาได้แน่นอน |  |  |
| ขยับตัวหรือพูดระหว่าง preview | แจ้งภาพเปลี่ยน/ให้นั่งนิ่งเมื่อ heuristic ตรวจพบ |  |  |
| สังเกตว่ามีการจับการเคลื่อนไหวได้หรือไม่ | ถ้ามีกราฟ ให้กราฟเปลี่ยนสัมพันธ์กับลมหายใจ; UI ปัจจุบันไม่มีกราฟ ให้บันทึกว่ายังไม่รองรับ |  |  |
| วัด RR แล้วนับด้วยมือครบ 60 วินาทีในรอบเดียวกัน | เป้าหมายที่เสนอคือคลาดเคลื่อนไม่เกิน ±2 ครั้ง/นาที แต่ app ปัจจุบันวัด 30 วินาที จึงเทียบตรงตาม protocol นี้ไม่ได้; บันทึกผลจริงและข้อจำกัด |  |  |
| ใช้งานบน Desktop | Navigation, preview และ controls ไม่ล้น/ทับกัน |  |  |
| ใช้งานบน Mobile viewport/อุปกรณ์จริง | Layout ปรับได้และ controls ใช้งานสะดวก |  |  |
| ใช้ keyboard-only: Tab, Enter, Space | ไปถึง Consent/ปุ่มต่าง ๆ ได้ มี focus ring และกดใช้งานได้ |  |  |
| ตรวจ Console | ไม่มี JavaScript error และไม่มีภาพ/เสียง/ข้อมูลสุขภาพใน log |  |  |
| ตรวจ Network | ไม่มีการส่งวิดีโอ/ภาพออกนอกเครื่องโดยไม่ได้ตั้งใจ (การดาวน์โหลด library/model เป็น request แยกต่างหาก) |  |  |

## บันทึกผลรวมการทดสอบ

| วันที่ | เบราว์เซอร์ | อุปกรณ์ | จำนวน PASS | จำนวน FAIL | ผู้ทดสอบ (ใช้ชื่อย่อได้) |
|---|---|---|---:|---:|---|
|  |  |  |  |  |  |

หากต้องส่งผลให้ผู้พัฒนา ให้ส่งเฉพาะตาราง PASS/FAIL, browser/version, device/OS, error message ที่ลบข้อมูลส่วนตัวแล้ว ห้ามส่งภาพใบหน้า ภาพกล้อง วิดีโอ เสียง หรือข้อมูลสุขภาพ
